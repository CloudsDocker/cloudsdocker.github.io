事情是这样的:我只想把 `fd -t f -e md` 改一下,列出"最近修改的 5 个 md 文件"。

就这么一个小需求,结果像拉线头一样,把 `fd`、`find`、`rg`、`xargs`、`touch` 整条命令行找文件的工具链全扯了出来——每个工具的冷门用法、彼此的分工、还有一堆藏在时间戳里的坑。这篇文章就是把那次"一路挖到底"的过程整理成一个连贯的整体,按程序员的使用顺序往下走。

如果你平时就靠 `find . -name` 和 `ls -lt | head` 混日子,这篇大概率能让你的命令行效率上一个台阶。

---

## 第一站:最初的那个需求

**直接答案:**

```bash
fd -t f -e md -X ls -t | head -5
```

拆开看:

- `fd -t f -e md`:找出所有 `.md` 文件(`-t f` 只要文件,`-e md` 按扩展名过滤)。
- `-X`:把所有结果一次性交给后面的命令,相当于 `ls -t file1 file2 ...`。小写 `-x` 是每个文件单独跑一次,那样排序就没意义了。
- `ls -t`:按修改时间排序,最新的在最前面。
- `head -5`:只取前 5 个。

想顺带看到修改时间:

```bash
fd -t f -e md -X ls -lt | head -6
```

这里是 `head -6`,因为 `ls -l` 会多输出一行 `total N`,取 5 会少一个文件。

**第一个坑:** `fd` 默认会跳过隐藏文件,也会跳过 `.gitignore` 里的文件。如果你的 `.md` 在 `.claude/` 之类的隐藏目录里,会被"吃掉",要加 `-H`(隐藏)或 `-I`(不看 ignore)。

这个答案能用,但它其实绕了路——`ls -t | head` 是在排序完再截断。下面会看到更直接的写法。

---

## 第二站:fd 的时间窗口与冷门神技

### 用时间条件代替排序

**直接答案:**

```bash
fd -e md --changed-within 2d
```

意思是"最近 2 天改过的 md 文件"。不用 `ls`,不用 `head`,时间条件直接写进查询里。

- 单位随便写:`30min`、`10h`、`2d`、`1week`。
- 也可以给绝对时间:`--changed-within "2026-11-01"` 或 `"2026-11-01 10:00:00"`。
- 反过来用 `--changed-before`,找"很久没动的僵尸文档",清理旧笔记特别爽。
- 想要范围,两个叠加:`--changed-within 30d --changed-before 7d`,就是"7 到 30 天前改过的"。

**区别:** `--changed-within` 只过滤,不排序。想要"最近的在最前",还得接 `-X ls -lt`。所以:要固定数量(最新 5 个)用 `ls -t | head`,要固定时间(今天改的)用 `--changed-within`。

### 文件名带空格不翻车

**直接答案:** 用 `fd` 自带的 `-x` / `-X` 基本就够了,它不经过 shell 拆词,所以 `my notes.md` 不会被劈成 `my` 和 `notes.md`。

只有在你非要接管道的时候,才需要这个组合:

```bash
fd -e md -0 | xargs -0 ls -t
```

`-0` 让 fd 用空字符(NUL)分隔结果,`xargs -0` 按空字符切。文件名里可以有空格、引号,甚至换行,都不怕。

**一个冷门坑:** `-X`(大写)在文件特别多时,会自动分批执行,因为命令行长度有上限。分批以后,`ls -t` 只会在每一批内部排序,"全局最新 5 个"就可能不准。`xargs` 也是同样的毛病。几百个 md 文件没事,扫整个 `node_modules` 或 monorepo 就要留心。

### `-x` 的占位符,大多数人只会 `{}`

其实有一整套占位符:

| 占位符 | 含义 | 例子 `src/a/foo.md` |
|---|---|---|
| `{}` | 完整路径 | `src/a/foo.md` |
| `{/}` | 文件名 | `foo.md` |
| `{//}` | 所在目录 | `src/a` |
| `{.}` | 去掉扩展名的路径 | `src/a/foo` |
| `{/.}` | 文件名去扩展名 | `foo` |

比如批量把 md 转成 html:

```bash
fd -e md -x pandoc {} -o {.}.html
```

### 其他好用的参数

- **按大小找**:`fd -S +1m` 找大于 1MB 的,`-S -10k` 找小于 10KB 的。
- **排除目录**:`fd -E node_modules -E .git`,多写几个 `-E` 就行。
- **限制深度**:`-d 2` 只往下找两层,在大仓库里快得离谱。
- **全路径匹配**:`-p` 让正则匹配整个路径,不只是文件名。
- **全开模式**:`-u` 等于 `-H -I`,隐藏文件、gitignore 的文件全包括,前面说的"文件被吃掉"问题一次解决。

**最大的坑:** `-x` 默认是并行执行的,输出顺序不固定。要按顺序就加 `-j 1`。批量改文件时,并行是快,但日志会乱。

## 第三站:fd 和 rg 联手

**直接答案:** fd 管"找哪些文件",rg 管"文件里搜什么",各干各的。

```bash
fd -e md --changed-within 2d -X rg -H "TODO"
```

意思是"最近 2 天改过的 md 里,哪里写了 TODO"。

**为什么要加 `-H`:** `rg` 只收到一个文件时,默认不显示文件名。`-X` 把文件交给它,碰巧只有一个结果,输出就没有文件名,你会一脸懵"这行是谁家的"。`-H`(`--with-filename`)强制显示文件名。

### rg 自己就能按时间排序

```bash
rg --files -g '*.md' --sortr modified | head -5
```

这条直接回答了最初的问题,一个 fd 都没用。`rg --files` 只列文件不搜内容,`--sortr modified` 是按修改时间倒序(`--sort` 是正序,最旧的在前)。fd 笑了笑,默默接过了"我只是个找文件的"的锅。

**坑:** 开了 `--sort` 以后,rg 会退化成单线程,大仓库里会慢。所以"先 fd 缩小范围,再 rg 搜内容"在大仓库里往往更快。

### 反过来也行:先搜内容,再按时间排

```bash
rg -l -0 "TODO" -g '*.md' | xargs -0 ls -t
```

`-l` 只输出含匹配的文件名,`-0` 配 `xargs -0` 防空格,`ls -t` 按时间排。

另外:fd 和 rg 默认都遵守 `.gitignore`、都跳过隐藏文件,所以搭档起来"口径一致",不会出现 fd 找到、rg 搜不到的怪事。要全开,两边都加 `-u`。

## 第四站:fd 和 find 的核心差异

**直接答案:** fd 是"日常好用的跑车",find 是"哪里都有的卡车"。能用 fd 就用 fd,但下面这些场景得请 find 出场。

| | fd | find |
|---|---|---|
| 默认匹配 | 正则(`-g` 切 glob) | glob(`-name`) |
| 大小写 | smart-case(全小写则忽略大小写) | 区分(`-iname` 才忽略) |
| 隐藏/gitignore | 默认跳过 | 全都看 |
| 并行 | 默认并行 | 单线程 |
| 到处都有 | 要装(Debian/Ubuntu 上叫 `fdfind`) | POSIX 自带 |

**什么时候必须用 find:**

1. **服务器上没装 fd。** 你 SSH 进一台干净的生产机,fd 不在,find 永远在。这是最现实的理由。
2. **按权限找:** `find . -perm -u+x`,fd 没有 `-perm`。
3. **自定义输出格式:** GNU find 的 `-printf` 很强,比如这条经典的"最近 5 个文件,带时间戳":

   ```bash
   find . -name '*.md' -printf '%T@ %p\n' | sort -nr | head -5
   ```

   `%T@` 是修改时间的 Unix 时间戳,排序又准又稳。
4. **复杂布尔逻辑:** `find` 支持 `-o`(或)、`-not`、括号分组。
   例如:`find . \( -name '*.log' -o -name '*.tmp' \) -mtime +30 -delete`,意思是"30 天前的 log 或 tmp 全删",一条命令搞定。
5. **`-prune` 剪枝:** 精准跳过某个目录而不进去,fd 的 `-E` 效果类似,但 find 的写法能和其他条件灵活组合。
6. **`-delete`、`-links`、`-newer 某文件`** 这类冷门判断,fd 要么没有,要么得绕路。

**最大的坑:** `find ... -delete` 的参数顺序有讲究,`-delete` 必须放在条件后面。如果写成 `find . -delete -name '*.tmp'`,find 会先删再判断,等于"全删"。删文件前先把 `-delete` 换成 `-print` 跑一遍预览,这是保命习惯。

**一句话选择法:** 交互式、日常找东西 → fd;写脚本要可移植、或要权限/格式化/复杂逻辑 → find。

## 第五站:find 的 `-exec {} +` vs `\;` vs xargs

**直接答案:** `\;` 是"一个文件叫一次外卖",`+` 是"凑够一单再叫"。能用 `+` 就用 `+`,快几十倍。

```bash
# 每个文件启动一次 ls,1000 个文件 = 启动 1000 次
find . -name '*.md' -exec ls -l {} \;

# 批量塞进一条命令,相当于 ls -l a.md b.md c.md ...
find . -name '*.md' -exec ls -l {} +
```

**为什么 `\;` 要加反斜杠:** `;` 在 shell 里是"命令结束"的意思,不转义的话,shell 会在 find 看到它之前就把命令劈成两半。写成 `';'` 也行。

**三者对比:**

| | `-exec ... \;` | `-exec ... {} +` | `\| xargs` |
|---|---|---|---|
| 调用次数 | 每个文件 1 次 | 分批,次数最少 | 分批 |
| `{}` 位置 | 随便放 | 必须紧挨 `+` 前面 | 要 `-I{}` 才能放中间 |
| 并行 | 不行 | 不行 | `-P 4` 可以 |
| 空文件名 | 自动正确 | 自动正确 | 要 `-print0 \| xargs -0` |
| 能当判断条件 | 能 | 不能 | 不能 |

**冷门神技 1:`\;` 可以当"测试条件"用**

```bash
find . -name '*.md' -exec grep -q "TODO" {} \; -print
```

`grep -q` 找到返回 0,`-exec` 就判为"真",后面的 `-print` 才会执行。这样能直接得到"含 TODO 的文件名"。`+` 做不到,因为它总是返回真,真正的结果要等最后才知道。

**冷门神技 2:`{}` 必须在最后怎么办?** 比如复制文件,目标目录得放最后:

```bash
find . -name '*.md' -exec cp -t /backup {} +
```

GNU `cp -t` 允许把目标目录提前,于是 `{}` 就能殿后了。`mv -t` 同理。macOS 的 BSD `cp` 没有 `-t`,那边只能用 `\;` 或 xargs。

**冷门神技 3:`-execdir` 和 `-ok`**

- `-execdir`:先 cd 到文件所在目录再执行,`{}` 变成 `./文件名`。在 `/tmp` 这类别人也能写的目录里更安全,能避免符号链接被调包的攻击。
- `-ok`:每次执行前都问你一句 y/n,批量删东西时当安全带。

**三个坑:**

1. **`+` 也会分批。** 文件太多时一样会被切成好几批,所以前面说的 `ls -t | head -5` 全局排序不准,在这里同样成立。
2. **`xargs` 遇到空输入会照跑一次。** `find` 什么都没找到,`xargs rm` 依然会执行一次没有参数的 `rm`。GNU 版加 `-r`(`--no-run-if-empty`)就好了。`find -exec +` 没匹配就不会执行,这点它更省心。
3. **退出码不一样。** `+` 里任何一批失败,find 最终返回非零。`\;` 的失败只影响那一次判断,find 本身照常退出 0。脚本里靠退出码判断成败时,要注意这点。

**怎么选:**

- 要判断条件,或每个文件要单独处理 → `\;`
- 普通批量操作 → `+`
- 要并行,或要接别的工具 → `-print0 | xargs -0 -P 4`

## 第六站:find 的时间判断 `-mtime` / `-mmin` / `-newer`

**直接答案:** `-mtime` 数的是"整 24 小时",而且会向下取整,所以 `-mtime 1` 不是"1 天前",而是"24 到 48 小时前"。

```bash
find . -name '*.md' -mtime -2    # 48 小时以内改过的
find . -name '*.md' -mtime +7    # 7 天以上没动过的(实际是 ≥ 8 天)
find . -name '*.md' -mtime 0     # 过去 24 小时内改过的
```

**三种写法的含义:**

| 写法 | 含义 | 白话 |
|---|---|---|
| `-mtime -n` | 少于 n 个 24 小时 | 最近 n 天内 |
| `-mtime n` | 恰好 n 个 24 小时(取整后) | 第 n 天那一个窗口 |
| `-mtime +n` | 多于 n 个 24 小时 | 比 n+1 天还早 |

**为什么 `+7` 是"≥ 8 天"?** find 先把文件年龄向下取整成整天数,再比较。一个 7.9 天前的文件,取整后是 7,不大于 7,所以 `+7` 抓不到它。必须满 8 天,取整后是 8,才算 `> 7`。这是整个 `-mtime` 最经典的坑。

**想要精确,别用 `-mtime`,用 `-mmin`:**

```bash
find . -name '*.md' -mmin -30    # 最近 30 分钟
find . -name '*.md' -mmin +1440  # 超过 24 小时,按分钟算,没有取整坑
```

**冷门神技 1:`-daystart`,按"今天 0 点"算**

```bash
find . -name '*.md' -daystart -mtime 0
```

不加的话,"0"是"过去 24 小时"。加了以后变成"从今天零点起",也就是"今天改过的"。注意它必须写在 `-mtime` 前面才生效。

**冷门神技 2:`-newer`,拿一个文件当时间标尺**

```bash
find . -name '*.md' -newer README.md
```

"比 README.md 还新的 md 文件"。配合 `touch` 做"检查点"特别好用:

```bash
touch /tmp/mark          # 打个标记
# ...干活...
find . -newer /tmp/mark  # 干活期间改了哪些文件
```

**冷门神技 3:`-newermt`,直接写日期(GNU find)**

```bash
find . -newermt "2026-11-01" ! -newermt "2026-11-04"
```

"11 月 1 日到 11 月 4 日之间改的"。`!` 是取反,两个条件夹出一个时间段。这个比 `-mtime` 直观太多。

**三个坑:**

1. **`-mtime` 看的是修改时间,不是创建时间。** 文件内容改了才更新;`mv` 重命名不会改它,`cp` 却会生成新的时间(除非加 `-p`)。
2. **`-atime` 别太信。** 很多系统挂载时用了 `relatime`/`noatime`,访问时间不是每次都更新。
3. **BSD/macOS 的 find 没有 `-newermt`。** 那边要么用 `-newer` 配 `touch -t` 造一个标尺文件,要么用 `-mtime`。

**一句话选择法:** 精确到分钟用 `-mmin`;"某个日期之后"用 `-newermt`;"比某文件新"用 `-newer`;`-mtime` 只在粗略按天、且你记得取整规则时用。

## 第七站:用 `touch` 凭空造时间,验证上面所有时间条件

**直接答案:** 想验证 find 的时间条件,别干等,直接用 `touch` 把文件时间"穿越"到过去。

```bash
touch -d "3 days ago" old.md          # GNU touch,可以写人话
touch -d "2026-11-01 10:30" a.md      # 指定日期时间
touch -t 202611011030 b.md            # 传统格式:YYYYMMDDhhmm
```

**两个参数的区别:**

| | `-d` | `-t` |
|---|---|---|
| 写法 | 自由文本、ISO 格式、`@时间戳` | 固定 `[[CC]YY]MMDDhhmm[.ss]` |
| GNU(Linux) | 支持人话,如 `"yesterday"` | 支持 |
| BSD(macOS) | 只认 ISO 8601,如 `2026-11-01T10:30:00`,不认 `"3 days ago"` | 支持 |

要写脚本、要可移植,用 `-t`,它到处都能跑。

**实战:搭一个测试沙盒,亲手验证第六站的"取整坑"**

```bash
d=$(mktemp -d) && cd "$d"
touch -d "7 days 22 hours ago" almost8.md   # 约 7.9 天前
touch -d "8 days ago" exactly8.md
find . -name '*.md' -mtime +7
```

预期结果是只有 `exactly8.md` 被抓到,`almost8.md` 逃过一劫。`mktemp -d` 造的是临时目录,玩坏了也不心疼。

**冷门神技:**

1. **`-r` 抄别人的时间**:`touch -r README.md new.md`,把 `new.md` 的时间设成和 `README.md` 一样。配合 `-newer` 测试特别顺手。
2. **只改一种时间**:`-m` 只改修改时间,`-a` 只改访问时间。测 `-atime` 和 `-mtime` 的差别就靠它。
3. **用 epoch 时间戳**:`touch -d @1730000000 x.md`,日志里抄来的时间戳直接用。
4. **`-c` 不创建**:`touch -c file`,文件不存在就什么都不做,不会凭空多出一个空文件。
5. **批量造阶梯文件**:

   ```bash
   for i in 1 2 3 4 5; do touch -d "$i days ago" "f$i.md"; done
   ```

   `f1` 到 `f5` 刚好错开一天,拿来测 `-mtime -3` 之类的条件一目了然。

**验证有没有造成功:**

```bash
ls -l --time-style=long-iso        # GNU
stat -c '%y %n' *.md               # GNU,精确到纳秒
stat -f '%Sm %N' *.md              # BSD/macOS
```

**四个坑:**

1. **ctime 伪造不了。** `touch` 能改 mtime 和 atime,但 ctime(状态改变时间)永远是"现在",内核不让你改。所以 `find -ctime` 没法用 touch 测。
2. **时区陷阱。** `-d "2026-11-01 10:30"` 按本地时区解释。想要确定的结果,写成 `-d "2026-11-01 10:30 UTC"`(GNU)。
3. **`touch` 已存在的文件不会清空内容**,只更新时间,放心用。但对只读文件会报 Permission denied。
4. **时间旅行不会骗过备份和构建工具。** `make`、`rsync` 这些就是靠时间戳判断的,乱改 mtime 可能让它们误以为"没变化"而跳过。别在真实项目里随手穿越。

## 收尾:一张"按需求选工具"的速查表

从一行 `fd` 出发,我们把整条找文件链路走了一遍。最后浓缩成一句句口诀:

- **找文件、交互用** → `fd`,记得 `-u` 收隐藏文件。
- **固定数量(最新 5 个)** → `... -X ls -t | head`。
- **固定时间窗口(今天/最近 2 天)** → `fd --changed-within`,或 `find -mmin` / `-newermt`。
- **可移植脚本、权限、花式输出** → `find`,`-printf '%T@ %p\n' | sort -nr` 是排序王牌。
- **批量执行** → 能 `+` 就 `+`,要判断条件用 `\;`,要并行用 `xargs -P`。
- **搜内容** → `rg`,它自己就能 `--sortr modified`。
- **测试时间条件** → `mktemp -d` 搭沙盒 + `touch -d` 造时间线。

一个"列出最近 5 个文件"的小问题,最后变成了一次完整的命令行基本功复盘。命令行就是这样,随便一根线头扯下去,后面都是一整套值得吃透的东西。
